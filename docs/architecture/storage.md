# Storage

The Storage window shows what builds use outside every project, grouped by platform: the dependency sources the engine's PC builds unpack into its `FRIED_DEPS_CACHE`, and the SDL2 libraries it compiles from them into `installed/` there and the tool's own w64devkit, Emscripten SDK and Fried Editor versions, which both grow with each version, and each console's SDK, found the way a build finds it (`VITASDK`, `DEVKITPRO`, and `<prefix>/share/fxsdk` beside the `fxsdk` command). Only what was downloaded can be deleted, because the engine and the tool fetch whatever is missing on the next build; an SDK came from its own installer, often as root, and deleting its folder would leave that installer's package database out of step, so it is only shown. The tool finds the dependency cache where the engine puts it by default, worked out the same way `cmake/PcDependencies.cmake` does, so a cache moved with `-DFRIED_DEPS_CACHE` is not listed. A source folder without the engine's `.fried-unpacked` marker, or an installed one without `.fried-installed`, is shown as incomplete, which is how the engine sees it too. Sizes are measured each time the window opens, on a thread of their own since an SDK runs to gigabytes, and links are not followed, so nothing is counted twice or outside its folder.
