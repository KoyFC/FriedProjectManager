# Fried Editor

The tool downloads Fried Editor from the repository's GitHub releases, any of them rather than one written in the code. The versions are the repository's tags, listed with `git ls-remote` the way the engine's versions are, and a release `v<version>` holds the file for each system and a `SHA256SUMS`. `editor_install.cpp` follows the shape of the w64devkit install: `beginInstall()` clears what an earlier attempt left and lists the commands (`curl` for the checksums and the file, the check, the unpacking) for the command window, and `finishInstall()` moves the result into place only once it is complete. The checksum comes from the same release as the file, so it catches a download that was cut short or garbled, but it is no defence against a release that was tampered with, which a checksum written in the tool's code would be. A tag with no published release fails at the first `curl`, and a tag that is not a plain version, such as a pre-release, is not offered.

Each version has a folder of its own, `editor/<version>` in the data folder, so a new one installs beside the others, one that fails with someone's project can still be run, and Storage deletes what is not wanted. The newest installed opens projects. A folder named `<version>-unpacking` is an install that did not finish, and Storage shows it as incomplete.

On Linux the release is an AppImage, which is unpacked once when it is installed and started through its `AppRun`. That way it runs without FUSE, which a distribution may not have, and starts faster than an AppImage that unpacks itself every time.

There is no choice of editor per project. Every release speaks the same protocol with the player, and an engine that does not is reported by the editor itself, which asks for the player to be rebuilt. A local build is used instead of any install, so the editor can be developed without publishing a release: the executable `FRIED_EDITOR` names, or else the build in a `FriedEditor` checkout beside this repository, found from the tool's own folder, since the repositories are siblings.

The editor builds a player from the project's engine the first time it opens, so before starting it the tool asks what a PC build asks, through FriedCore's `Build::steps`: Haxe and CMake on the `PATH`, and on Windows Visual Studio or w64devkit. A machine that lacks one is told what, and may open the editor anyway, since a player built before still works.
