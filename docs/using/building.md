# Building

**Build** (Ctrl+B) runs the whole pipeline for the selected target in a window that streams the output, colors it by message type, shows how long it has been running, reports how long it took once it is done and offers to open the build folder:

```sh
haxe build.hxml
cmake -S . -B build[/windows|/vita|/switch|/3ds|/nds|/cg50|/android|/web] -DCMAKE_BUILD_TYPE=Debug [-DCMAKE_TOOLCHAIN_FILE=<the target's>]
cmake --build build[/windows|/vita|/switch|/3ds|/nds|/cg50|/android|/web] --config Debug --parallel
```

A Windows build from Linux needs the MinGW-w64 cross compiler, `x86_64-w64-mingw32-g++`, on the `PATH` and uses the toolchain file the engine ships in `engine/cmake/toolchains/mingw-w64.cmake`; Wine runs the result. A Vita build needs `VITASDK` set, a Switch, 3DS or DS build needs `DEVKITPRO`, and an fx-CG50 build needs the fxSDK's `fxsdk` command on the `PATH`, which is how its toolchain file is found. A web build needs the Emscripten SDK, found through `EMSDK` (set by its `emsdk_env.sh`), in `~/emsdk` or in the copy the tool downloads for itself, which it offers to do, into its own data folder, when it finds none (this needs `git` and Python); the result is an `.html` with its `.js`, `.wasm` and `.data`, to be served over HTTP rather than opened from disk. An Android build needs the Android NDK, an SDK with platform 35 and build-tools 35.0.1, and a JDK, found through `ANDROID_NDK_ROOT`, `ANDROID_HOME` and `JAVA_HOME` (or `javac` on the `PATH`) or in the copies the tool downloads for itself on Linux, about a gigabyte after the license is accepted; the result is an arm64 `.apk` signed with the debug key. All of them need `haxe` on the `PATH` the tool itself was started with, and every one but a PC build on Windows needs `cmake` there too.

On Windows, a PC build uses Visual Studio's C++ tools when they are installed, with the `cmake` on the `PATH` or else the one Visual Studio installs for itself. Without them, the first build offers to download [w64devkit](https://github.com/skeeto/w64devkit) 2.10.1, about 70 MB with GCC, CMake and Ninja, into `%LOCALAPPDATA%\Fried Engine\Fried Project Manager\tools`, checks it against its known SHA-256 and builds with it from then on, with the Ninja generator, so the executable lands directly in the build folder. Neither one is put on the system `PATH`. Switching between the two needs a fresh build folder, since CMake keeps the generator it first configured a folder with.

Choosing a platform in the sidebar selects its target in the build bar, and the PC page, which covers every desktop target, keeps a Windows-from-Linux or web target already chosen. The build bar names the PC target for the system the tool runs on (Linux, Windows or macOS). **Build type**, **Log to file** and **Build directory** are remembered per project and per target, defaulting to `Debug`, unchecked and to `build`, `build/windows`, `build/vita`, `build/switch`, `build/3ds`, `build/nds`, `build/cg50`, `build/android` and `build/web`. The directory field is editable in full, with `{project}` standing for the project's own directory. Debug builds the Haxe side with `-debug`, so the engine logs where each message came from, and **Log to file** adds `-D fried_log_file`, so the game also writes `Player.log` in its user data folder.

Each platform's page shows whether it can be built on this machine, from the same checks a build makes, with the reason when it cannot and a **Download** button where the tool can fetch a compiler, and the exact commands the build bar would run, to copy into a terminal.

A generated project also compiles by hand: `haxe build.hxml`, then `cmake -S . -B build && cmake --build build`, or the same with `-DCMAKE_TOOLCHAIN_FILE=engine/cmake/toolchains/mingw-w64.cmake` for a Windows `.exe` from Linux, `-DCMAKE_TOOLCHAIN_FILE=$VITASDK/share/vita.toolchain.cmake` for a `.vpk`, `-DCMAKE_TOOLCHAIN_FILE=$DEVKITPRO/cmake/Switch.cmake` for a `.nro`, `-DCMAKE_TOOLCHAIN_FILE=$DEVKITPRO/cmake/3DS.cmake` for a `.3dsx`, `-DCMAKE_TOOLCHAIN_FILE=$DEVKITPRO/cmake/NDS.cmake` for a `.nds` and `-DCMAKE_TOOLCHAIN_FILE=<fxSDK prefix>/lib/cmake/fxsdk/FXCG50.cmake` for a `.g3a`, and `-DCMAKE_TOOLCHAIN_FILE=$EMSDK/upstream/emscripten/cmake/Modules/Platform/Emscripten.cmake` for the web. Cloning the submodule needs `git` and network access to the engine repository.
